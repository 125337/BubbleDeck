# BubbleDeck 插件端 · V2 按包授权接入方案

> 2026-11-03。对接 V2 授权 API（`https://qb.xhhan.xyz/bd/*`），契约见 [授权系统方案.md](授权系统方案.md)。
> V2 核心：**插件免费壳，一包一码，wxid 绑定，服务器下发授权清单为唯一真话来源。**

## 总览

```
微信启动 → dylib 加载
  └─ 后台线程报到 POST /packs（带 wxid+IDFV）
        ├─ 成功 → 缓存清单（Keychain, 带时间戳）→ 按清单刷新在线包 UI / 禁用失效包
        ├─ wxid 抓不到 → 用 Keychain 上次缓存的 wxid（账号一般不变）
        └─ 网络失败 → 沿用缓存清单；缓存超 7 天 → 在线包全禁用（本地导入包不受限）
```

无 token、无 verify、无自动重激活——V2 客户端授权逻辑比 V1 净减 ~100 行。

## 文件改动

| 文件 | 改动 |
|---|---|
| `Core/TDNet.h/.m` | 四接口 → 两接口：`activate`、`packs`（签名逻辑不变） |
| `Core/TDLicense.h/.m` | 重写：`activateLicense:completion:`（输码入账，成功即忘码，内部同步报到拉回授权）+ `refreshEntitlements`（启动报到，缓存 owned 清单）+ Keychain 只存 wxid 缓存/清单缓存/时间戳。删 token 状态机、自愈、兜底计时 |
| `Entry/TDBubbleEntry.m` | 删全局激活卡；在线包每行三态：**未拥有**→[输码激活]，**已拥有未下载**→[下载]（激活成功自动高亮），**已下载**→进本地列表。未拥有包显示名称/版本/大小（橱窗效应） |
| `Engine/TDBubbleEngine.m` | 闸门 ~30 行：启动报到后，凡是「在线来源且 enabled 且不在 owned 清单」的包自动禁用。本地导入包不校验（免费壳） |
| `Core/TDConfig` | 包记录加 `source` 标记（online/imported），闸门和 UI 用 |

## 交互流

```
买卡 → 插件设置页在线包区 → 蜜糖邦尼[输码激活] → 弹窗输码
  → /activate（wxid+IDFV 自动带）→ 成功 toast「已激活·蜜糖邦尼气泡包」
  → 自动刷新清单 → 该包变[下载]高亮 → 下载（进度/md5/解密解压）→ 本地列表出现 → 启用生效
封卡/换号 → 下次启动报到 owned:false → 自动禁用 → 气泡回官方图
```

错误码转人话：1001 卡不存在 / 1002 已停用 / 1005 此码已绑定其他微信号（重新购买）/
4003 网络异常。
wxid 抓不到时激活按钮提示「请先登录微信后再激活」。

## 离线兜底（对齐 V1 体验）

- 清单缓存 = Keychain JSON + 上次成功时间戳
- 断网：沿用旧清单，已下载包照常用（体验优先）
- 缓存 >7 天（用户长期断网/屏蔽网络）：在线包全禁用，恢复网络报到后自动恢复
- 本地导入包永不参与兜底逻辑

## 已知妥协（继承 V1 + V2 新增）

1. V1 全部继承：SALT 可 dump、patch 闸门即破解、买家转发 zip 防不住
2. **wxid/IDFV 双绑**：冒领需同时伪造两值，但越狱环境均可改——挡住绝大多数，V2 明确接受
3. **在线包禁用后文件仍在本地**：重新拥有（换号买新码）秒恢复无需重下；备份文件+手动导入可绕过（免费壳模型下「导入」本来就是合法功能，不视为破解点）

## 实施顺序

1. 服务器 V2（app.py + manage.py）→ 本地回环测试 → 部署
2. TDNet + TDLicense 改造（纯逻辑）

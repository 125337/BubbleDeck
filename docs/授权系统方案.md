# BubbleDeck 授权系统方案 V2（评审稿）

> 2026-11-03 · V2：**按包收费 + wxid 绑定**。V1（整套插件一张全局卡）已废弃，文末附差异表。
> 客户端实施细节见 [客户端方案.md](客户端方案.md)。

## 一、业务模型

```
插件本体 = 免费壳（随便装，本地导入功能不设限）
气泡包   = 付费内容，一码 = 一个气泡包

买卡（某包的码）→ 插件里输一次码入账 → 码的使命结束
之后一切以服务器下发的授权清单为准：
  每次启动微信 → 客户端带 wxid+设备 报到 → 服务器回「你有哪些包」
  → 清单驱动：UI 状态、下载放行、封卡生效、换号失效
```

## 二、绑定规则

| 项 | 规则 |
|---|---|
| 绑定主键 | **wxid（微信账号）**——码跟着号走 |
| 绑定规则 | **一次绑定，永久生效，不可换绑**：首输码者拥有该码；码已绑 A 号后 B 号再输 → 拒绝，提示重新购买 |
| device_id | IDFV，**仅记录展示，不参与校验**（码认号不认机：换手机/重装微信，同号照常用） |
| 同号重复输码 | 幂等成功（提示已激活），服务器更新 device 记录 |
| 换微信号 | 等于新用户：要用得买新码；旧绑定不动（原号回来还能用） |
| 有效期 | 永久，无续费概念 |
| 封卡 | 后台 revoke → 下次报到授权清单里该包消失 → 客户端自动禁用（气泡回官方图），只影响该包 |
| 服务器下发 | 唯一真话来源，客户端本地判断不作数 |

## 三、接口契约（四接口简化为两个业务接口）

通用约定不变：`https://qb.xhhan.xyz/bd/*`，全 POST + JSON，请求头 `X-BD-Ts`（毫秒）+
`X-BD-Sign = HMAC-SHA256(SALT, "{ts}|{body}")`，±300s。响应 `{code, msg, data}`。

> **V2 去掉了 token/verify/download**：wxid+IDFV 双绑本身就是凭证，token 状态机（过期/
> 续期/兜底）全部不需要；key 直接随授权清单下发，下载走公开直链。

### 1. 激活（入账）`POST /activate`

```jsonc
// 请求
{ "license": "XXXX-XXXX-XXXX-XXXX", "device_id": "IDFV", "wxid": "wxid_xxx",
  "sys": "iOS 17.2.1", "model": "iPhone16,1" }
// 成功 data
{ "pack_name": "蜜糖邦尼气泡包" }        // 同号重复输码也走这里（幂等）
// 失败 code
// 1001 卡密不存在  1002 卡密已停用  1004 参数缺失
// 1005 此码已绑定其他微信号（拒绝，提示重新购买）
```

规则：
- `unused` 卡 → 绑定 (pack, wxid)，记录 device，state→active
- 同卡同 wxid 再次输码 → 幂等成功，刷新 device 记录（不设次数上限——绑定键只有 wxid，设备不校验）
- 码已绑 A 号、B 号来输 → 1005，一票否决，无任何重置通道（除非后台手工处理）
- wxid 抓取失败（空）→ 客户端本地拦住不给发（绑定主键就是 wxid）

### 2. 授权清单 + 商店橱窗 `POST /packs`

```jsonc
// 请求（每次微信启动报到一次）
{ "device_id": "IDFV", "wxid": "wxid_xxx" }
// 成功 data
{ "packs": [
    { "name": "蜜糖邦尼气泡包", "version": "1.0", "size": 1836261,
      "md5": "...", "url": "https://...bdpack",
      "owned": true,  "key": "32字符" },      // owned 包带 key
    { "name": "星河气泡包", "version": "1.2", "size": 2200000,
      "md5": "...", "url": "https://...bdpack",
      "owned": false, "key": null }           // 未拥有：橱窗展示，无 key
] }
```

- 一次报到拿全量：拥有包的 key 随清单下发（HTTPS 内传输，无需单独 download 接口）
- 封卡/换号 → 下次报到 `owned:false` + 无 key → 客户端自动禁用该包
- **离线兜底**：客户端缓存上次清单+时间戳，断网沿用旧清单（最多 7 天，超期在线包全禁用，恢复网络自动恢复）

### 签名/防抓包

同 V1：SALT 内置 dylib，挡小白不挡逆向，V1 已知妥协全部继承。

## 四、包加密机制（不变）

同 V1：`.bdpack` = `BDPK` 魔数(4B) + 版本(1B) + 随机 IV(16B) + AES-256-CBC(标准 zip, PKCS7)。
密钥每包一个，存服务器 packs 表，仅随授权清单下发给 owned 用户。打包端 tools/pack.py 不变。
**V2 差异**：泄露轮换时重打包后，已 owned 用户下次报到自动拿到新 key，无需发新码。

## 五、卡密设计

- 格式不变 `XXXX-XXXX-XXXX-XXXX`；状态机 `unused → active → (revoked)`
- 服务端 licenses 表 V2 字段：`license, pack_name, state, bind_wxid, bind_device, activated_at`（去掉 token/token_exp/rebind_left/activate_count）
- **发卡必须带包名**：`python3 manage.py gencards 10 --pack 蜜糖邦尼气泡包`

## 九、V1 → V2 差异表

| 项 | V1 | V2 |
|---|---|---|
| 收费粒度 | 整套插件一张卡 | 一包一码，插件免费 |
| 绑定键 | license ↔ device（wxid 仅记录） | **license ↔ (pack, wxid)**，一次绑定不可换绑 |
| 接口 | activate/verify/packs/download | **activate/packs**（去 verify/download） |
| token | 30 天滚动 + 7 天兜底 + 自动重激活 | 无 token；清单缓存 7 天兜底 |
| 客户端 Keychain | token+卡密+device | 仅 wxid 缓存+清单缓存（敏感信息趋零） |
| 封卡影响 | 插件全废 | 仅该包失效 |
| 换号 | 无影响（wxid 不校验） | 该包失效，需重新买 |
| 换机 | 不支持，重新发卡 | 码认号不认机，同号照常用 |

# BubbleDeck 授权系统方案 V3（评审稿）

> 2026-11-04 · V3：在 V2（按包收费 + wxid 绑定）基础上，吸收 ThemePro 4.9.6 / ThemeLab 1.7.4
> 两套商业方案的实测逆向结论，补齐**包加密（盘上常密）与完整性校验**。
> V2 的业务模型（一码一包、wxid 首绑、无 token、双接口）**全部保留**，文末附 V1→V2→V3 演进表。
> 客户端实施细节见 [客户端方案.md](客户端方案.md)。

## 〇、V3 增补摘要（相对 V2）

| # | 增补 | 依据（实测） |
|---|---|---|
| 1 | `.bdpack` 升级 **BDP2 容器**：AES-256-GCM（AAD 绑包名版本），**安装零解压、盘上常密** | ThemePro 工作束 WebDAV 实锤：盘上永远密文，取图瞬间才内存解密；V2 明文落盘比它弱一档 |
| 2 | GCM tag 取代 md5 作内容完整性（md5 保留作传输校验） | CBC 无完整性：篡改/拼接容器只能靠 zip 结构偶检 |
| 3 | 钥匙串清单缓存显式 **ThisDeviceOnly** | 防 iCloud/备份把含 key 的清单带走 |
| 4 | activate/packs **限频**（同 device_id/IP 30 次/时 → 1007） | 免费额度也是额度，防脚本刷 |
| 5 | 发卡 CSPRNG（`secrets`，已用 ✓ 写入规范） | 卡密熵要有资格配它的价值 |

V2 已做对的（保持不动）：wxid 首绑永久、码认号不认机、去 token、key 随清单下发、
公开直链 + 密钥分离、离线 7 天兜底、封卡只影响单包——这套和 ThemePro/ThemeLab 的
账号粒度完全对齐，且比它们干净（无指纹漂移问题）。

## 一、业务模型（继承 V2）

```
插件本体 = 免费壳（随便装，本地导入功能不设限）
气泡包   = 付费内容，一码 = 一个气泡包

买卡 → 插件里输一次码入账 → 码的使命结束
之后一切以服务器下发的授权清单为准：
  每次启动微信 → 客户端带 wxid+设备 报到 → 服务器回「你有哪些包（含密钥）」
  → 清单驱动：UI 状态、下载放行、封卡生效、换号失效
```

## 二、绑定规则（继承 V2，微调措辞）

| 项 | 规则 |
|---|---|
| 绑定主键 | **wxid（微信账号）**——码跟着号走 |
| 绑定规则 | 一次绑定，永久生效，不可换绑：首输码者拥有该码；已绑 A 号后 B 号再输 → 1005 拒绝 |
| device_id | IDFV，仅记录展示 + 设备数统计（同号去重 ≤3 台软上限），**不参与校验**（码认号不认机） |
| 同号重复输码 | 幂等成功（提示已激活） |
| 换微信号 | 等于新用户：要用得买新码；旧绑定不动（原号回来还能用） |
| 有效期 | 永久 |
| 封卡 | 后台 revoke → 下次报到清单里该包消失 → 自动禁用该包 |
| 服务器下发 | 唯一真话来源 |

> wxid 相对 IDFV/微信号作键的理由：wxid 永不变（无 IDFV 重装陷阱、无微信号改名漂移），
> 且它由客户端从 CContactMgr 实时抓取，无需用户手输。

## 三、接口契约（两个业务接口，不变）

通用：`https://qb.xhhan.xyz/bd/*`，POST + JSON，`X-BD-Ts` + `X-BD-Sign = HMAC-SHA256(SALT, "{ts}|{body}")`，±300s。响应 `{code, msg, data}`。

### 1. 激活（入账）`POST /activate`

```jsonc
// 请求
{ "license": "XXXX-...", "device_id": "IDFV", "wxid": "wxid_xxx",
  "sys": "iOS 17.2.1", "model": "iPhone16,1" }
// 成功 data
{ "pack_name": "蜜糖邦尼气泡包" }
// 失败：1001 不存在 1002 停用 1004 缺参
//       1005 已绑其他微信号（一票否决）
```

新增：**限频**——同 device_id/IP 对 activate 合计 ≥ 20 次/小时 → 1007（SCF 内存计数即可）。

### 2. 授权清单 + 橱窗 `POST /packs`

```jsonc
// 请求（每次微信启动报到一次）
{ "device_id": "IDFV", "wxid": "wxid_xxx" }
// 成功 data
{ "packs": [
    { "name": "蜜糖邦尼气泡包", "version": "1.1", "size": ..., "md5": "...",
      "url": "https://...bdpack", "owned": true,  "key": "<base64 32B>", "ver": 2 },
    { "name": "星河气泡包", ..., "owned": false, "key": null } ] }
```

- owned 包带 `key/ver`；未拥有仅橱窗展示
- 封卡/换号 → 下次报到 `owned:false` → 自动禁用
- 离线兜底：缓存上次清单+时间戳，断网沿用 ≤7 天（Keychain，**ThisDeviceOnly**，V3 新增）
- **限频**：同 device_id/IP ≥ 60 次/小时 → 429

## 四、包加密机制（V3 核心 change）

### 4.1 容器格式 BDP2

```
偏移   内容
0      "BDP2" 魔数(4B)
4      ver = 2 (1B)
5      IV 12B（GCM nonce，打包随机）
17     密文体 = AES-256-GCM(内层 zip)
末尾   tag 16B
AAD    = "bdpack2|" + 包名 + "|" + 版本
```

- 算法：AES-256-GCM（`CCCryptorGCMOneshotEncrypt/Decrypt`，iOS 9+）——
  tag 自带完整性（防篡改/拼接/跨包），且 CTR 结构支持按需解密；
- V1 的 BDPK/CBC 容器继续可解（ver=1 分支），在线包逐步重下发为 ver=2；
- 明文 imported 包不加密不受限（免费语义不变）。

### 4.2 安装流程（V3：零解压、零明文落盘）

```
V2：下载 → 解密 → 解压 temp → 搬 packs/<名>/（明文 PNG 落盘）   ← 弱点
V3：下载 → md5 校验 → TDContainer open 试解密（钥匙错/文件坏在此报错）
    → 容器密文原样写 packs/<名>/pack.bdpack + meta.json
    （无 temp、无明文文件，文件管理器/备份/整包拷贝见到的全是密文）
```

### 4.3 取图（运行时）

```
bubbleImageForName: → online 包：TDContainer 惰性 open（每包一次，
    解密后 zip 常驻内存 2-5MB，memory warning 清）→ 按条目 inflate → UIImage
  → s_imgCache（路径 key，机制不变）
imported 包：原 imageWithContentsOfFile 分支不变
```

对齐实测：ThemePro 工作束同理（盘上 K2 密文、取图内存解密）——本方案用 GCM
替代其 CBC+零 IV，且无临时文件残留。

### 4.4 密钥生命周期

```
打包：随机 32B/包/版本 → 服务器 keys 表 {pack, version → key}
下发：/packs 仅对 owned 包带 key（HTTPS 内）
轮换：泄露事件 → 重打包换钥 → owned 用户下次报到自动拿新 key（V2 机制继承）
不落盘：keyForPack: 内存缓存；Keychain 清单缓存 ThisDeviceOnly
```

## 五、卡密设计（继承 V2）

- 格式/状态机不变；发卡必须带包名；`secrets` CSPRNG（V3 规范化）
- licenses 表（按卡一文件 `licenses/<key>.json`，V3 存储）：`license, pack_name, state, bind_wxid, devices{idfv: activated_at}, activated_at`
- 去掉 token 相关字段（V2 已去）

## 六、管理后台（继承 V2 需求）

发卡加包选择下拉；卡密列表加 pack_name 列；概览可选售出统计。

## 七、数据迁移

- V2 测试卡作废重发（带包名）
- packs 表 url/key/md5 复用；**key 复用但容器需重打包为 BDP2**（CBC→GCM 一次性迁移，脚本化）
- 客户端旧缓存自动清理（V2 机制继承）

## 十、已知妥协（V3 明确接受）

1. SALT 内置 dylib → 防小白不防逆向（出现真实破解事件：先上设备公钥包装 S3，再上水印）
2. wxid 客户端可声称 → 改客户端可冒充（防小白范围外；首绑 + IDFV 记录可定位滥用人）
3. 服务器泄露 = packKey 全沦陷 → 密钥库与授权库分离部署
4. 越狱内存截获不防（所有客户端 DRM 的天花板；V3 备选：买家水印溯源——打包时按订单
   往某资源嵌 license 标记，泄露可定位到人，对按包收费模式性价比最高）

## 十一、验收清单

- ☐ 一码一包：A 包的码激活不了 B 包
- ☐ wxid 首绑：已绑号外他号输码 1005；同号重复输码幂等
- ☐ 同号换设备/重装微信：IDFV 变 → 照常（码认号不认机）
- ☐ 封卡 → 下次报到该包 owned:false → 自动禁用
- ☐ 断网 ≤7 天沿用缓存；超期 online 包禁用、恢复自动恢复
- ☐ 下载 BDP2 → 错 key 安装报人话错误；篡改 1 字节 GCM 失败；AAD 改包名失败
- ☐ 盘上检查 packs/：只有 pack.bdpack + meta.json，无明文 PNG
- ☐ 未激活设备：hook 空转放行官方图
- ☐ 明文 imported 包不受影响
- ☐ activate 高频 → 1007

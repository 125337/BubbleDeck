# BubbleDeck 授权系统方案 V4（现行版）

> 2026-11-05 · V4：信任架构重构——**客户端零秘密 + key 现取现用**。
> V3 的包加密（BDP2/AES-256-GCM/盘上常密）与业务模型（一码一包、wxid 首绑、双接口）**全部保留**；
> V4 删除的是：dylib 内置 SALT、请求签名头、Keychain 清单落盘。文末附演进表与妥协清单。
> 客户端实施细节见 [客户端方案.md](客户端方案.md)。

## 〇、V4 增补摘要（相对 V3）

| # | 变更 | 理由 |
|---|---|---|
| 1 | **删 SALT + 请求签名**（dylib 与 app.py 双侧） | SALT 同时签后台/商家 cookie 与客户端请求——插件被逆向 = 后台可被接管。V4 后台会话改用服务器端独立密钥（session.py：BD_ADMIN_SECRET / BD_BIZ_SECRET，scope 混签），dylib 内零秘密 |
| 2 | **key 现取现用**：清单（含 key）仅进程内存，绝不落盘；启动/商店页/激活后现取 | 沙盒/备份/砸壳只有密文；封卡与换 key 即时生效（每进程内持续鉴权） |
| 3 | 限频放宽并只留一条：activate 100 次/时、packs 120 次/时（同 device_id\|IP） | 限频是减速带不是防线，按真实用量 10 倍冗余设置，绝不误伤正常买家 |
| 4 | 服务器顺手修复：商家解封 prev_state（修激活假成功）、上传 0 图拒收、删包挂卡全量检查 | 见 admin.py / biz.py |

> 信任模型一句话：**插件随便抄**——里面没有盐、没有签名、没有 key，抄到的只是个空壳客户端；
> 值钱的东西（双 secret、卡密、限频、keys 表）全在服务器上。

## 〇A、V3 增补摘要（相对 V2，历史）

| # | 增补 | 依据（实测） |
|---|---|---|
| 1 | `.bdpack` 升级 **BDP2 容器**：AES-256-GCM（AAD 绑包名版本），**安装零解压、盘上常密** | ThemePro 工作束 WebDAV 实锤：盘上永远密文，取图瞬间才内存解密；V2 明文落盘比它弱一档 |
| 2 | GCM tag 取代 md5 作内容完整性（md5 保留作传输校验） | CBC 无完整性：篡改/拼接容器只能靠 zip 结构偶检 |
| 3 | 发卡 CSPRNG（`secrets`，已用 ✓ 写入规范） | 卡密熵要有资格配它的价值 |

V2 已做对的（保持不动）：wxid 首绑永久、码认号不认机、去 token、key 随清单下发、
公开直链 + 密钥分离、离线 7 天兜底、封卡只影响单包——这套和 ThemePro/ThemeLab 的
账号粒度完全对齐，且比它们干净（无指纹漂移问题）。

## 一、业务模型（继承 V2）

```
插件本体 = 免费壳（随便装，本地导入功能不设限）
气泡包   = 付费内容，一码 = 一个气泡包

买卡 → 插件里输一次码入账 → 码的使命结束
之后一切以服务器下发的授权清单为准：
  每次启动微信 → 客户端带 wxid+设备 报到 → 服务器回「你有哪些包（含密钥）」
  → 清单驱动：UI 状态、下载放行、封卡生效、换号失效
```

## 二、绑定规则（继承 V2，微调措辞）

| 项 | 规则 |
|---|---|
| 绑定主键 | **wxid（微信账号）**——码跟着号走 |
| 绑定规则 | 一次绑定，永久生效，不可换绑：首输码者拥有该码；已绑 A 号后 B 号再输 → 1005 拒绝 |
| device_id | IDFV，仅记录展示 + 设备数统计（同号去重 ≤3 台软上限），**不参与校验**（码认号不认机） |
| 同号重复输码 | 幂等成功（提示已激活） |
| 换微信号 | 等于新用户：要用得买新码；旧绑定不动（原号回来还能用） |
| 有效期 | 永久 |
| 封卡 | 后台 revoke → 本进程内下次报到即失效；重启后必联网现取 → 气泡当场禁用 |
| 服务器下发 | 唯一真话来源 |

> wxid 相对 IDFV/微信号作键的理由：wxid 永不变（无 IDFV 重装陷阱、无微信号改名漂移），
> 且它由客户端从 CContactMgr 实时抓取，无需用户手输。

## 三、接口契约（两个业务接口，不变）

通用：`https://qb.xhhan.xyz/bd/*`，POST + JSON，**无请求签名**（V4 客户端零秘密）。响应 `{code, msg, data}`。

### 1. 激活（入账）`POST /activate`

```jsonc
// 请求
{ "license": "XXXX-...", "device_id": "IDFV", "wxid": "wxid_xxx",
  "sys": "iOS 17.2.1", "model": "iPhone16,1" }
// 成功 data
{ "pack_name": "蜜糖邦尼气泡包" }
// 失败：1001 不存在 1002 停用 1004 缺参
//       1005 已绑其他微信号（一票否决）
```

限频：同 device_id/IP 对 activate 合计 ≥ 100 次/小时 → 1007（实例内存滑动窗口）。

### 2. 授权清单 + 橱窗 `POST /packs`

```jsonc
// 请求（每次微信启动报到一次）
{ "device_id": "IDFV", "wxid": "wxid_xxx" }
// 成功 data
{ "packs": [
    { "name": "蜜糖邦尼气泡包", "version": "1.1", "size": ..., "md5": "...",
      "url": "https://...bdpack", "owned": true,  "key": "<base64 32B>", "ver": 2 },
    { "name": "星河气泡包", ..., "owned": false, "key": null } ] }
```

- owned 包带 `key/ver`；未拥有仅橱窗展示
- 封卡/换号 → 下次报到 `owned:false` → 自动禁用（本进程内下次报到生效；重启后必联网）
- **key 现取**：清单仅进程内存持有，绝不落盘；断网 = 本进程沿用内存清单，重启后必须联网现取
- 限频：同 device_id/IP ≥ 120 次/小时 → 429

## 四、包加密机制（V3 核心 change）

### 4.1 容器格式 BDP2

```
偏移   内容
0      "BDP2" 魔数(4B)
4      ver = 2 (1B)
5      IV 12B（GCM nonce，打包随机）
17     密文体 = AES-256-GCM(内层 zip)
末尾   tag 16B
AAD    = "bdpack2|" + 包名 + "|" + 版本
```

- 算法：AES-256-GCM（`CCCryptorGCMOneshotEncrypt/Decrypt`，iOS 9+）——
  tag 自带完整性（防篡改/拼接/跨包），且 CTR 结构支持按需解密；
- V1 的 BDPK/CBC 容器继续可解（ver=1 分支），在线包逐步重下发为 ver=2；
- 明文 imported 包不加密不受限（免费语义不变）。

### 4.2 安装流程（V3：零解压、零明文落盘）

```
V2：下载 → 解密 → 解压 temp → 搬 packs/<名>/（明文 PNG 落盘）   ← 弱点
V3：下载 → md5 校验 → TDContainer open 试解密（钥匙错/文件坏在此报错）
    → 容器密文原样写 packs/<名>/pack.bdpack + meta.json
    （无 temp、无明文文件，文件管理器/备份/整包拷贝见到的全是密文）
```

### 4.3 取图（运行时）

```
bubbleImageForName: → online 包：TDContainer 惰性 open（每包一次，
    解密后 zip 常驻内存 2-5MB，memory warning 清）→ 按条目 inflate → UIImage
  → s_imgCache（路径 key，机制不变）
imported 包：原 imageWithContentsOfFile 分支不变
```

对齐实测：ThemePro 工作束同理（盘上 K2 密文、取图内存解密）——本方案用 GCM
替代其 CBC+零 IV，且无临时文件残留。

### 4.4 密钥生命周期

```
打包：随机 32B/包/版本 → 服务器 keys 表 {pack, version → key}
下发：/packs 仅对 owned 包带 key（HTTPS 内）
现取：V4 起清单（含 key）仅进程内存，启动/商店页/激活后现取，绝不落盘
      （V3 曾用 Keychain 清单缓存 ThisDeviceOnly，V4 删除）
轮换：泄露事件 → 重打包换钥 → owned 用户重启现取自动拿新 key
```

## 十、已知妥协（V4 重新核定）

1. **买家自泄 key = 商业模式天花板**：同包所有买家共用一把 key，任何买家把 /packs
   响应里的 key 转发出去 = 白嫖。技术不可解（客户端必须有 key 才能解密），
   不做水印溯源（性价比不成立）。事件响应：封卡（V4 即时生效）+ 换 key 重签重发。
2. **wxid 客户端可声称 ≈ 买家自泄**：知道某买家 wxid 可拉其 key，但拉到的与买家自己
   持有的是同一把（key 按包共发），无增量危害。限频作减速带（批量扫号变慢变吵，
   日志可见）。客户端零秘密与"防 wxid 声称"在密码学上互斥，选前者。
3. **断网 = 在线包不可用**（现取形态固有代价）：会话内不受影响；重启后首次进商店/主题页
   需联网。微信重度联网，实际影响可忽略。
4. **服务器泄露 = keys 表沦陷** → 密钥库与授权库分离部署；泄露事件按包换 key 重签。
5. 越狱内存截获不防（所有客户端 DRM 的天花板：进程内存里永远存在解密后的 zip）。

## 十一、验收清单

- ☐ 一码一包：A 包的码激活不了 B 包
- ☐ wxid 首绑：已绑号外他号输码 1005；同号重复输码幂等
- ☐ 同号换设备/重装微信：IDFV 变 → 照常（码认号不认机，现取形态下重装免重输码）
- ☐ 封卡 → 重启现取后该包 owned:false → 自动禁用；本进程内下次报到即失效
- ☐ 重启后断网：在线包禁用（现取失败）；恢复联网自动恢复
- ☐ 下载 BDP2 → 错 key 安装报人话错误；篡改 1 字节 GCM 失败；AAD 改包名失败
- ☐ 盘上检查 packs/：只有 pack.bdpack + meta.json，无明文 PNG；**Keychain 无 entitlements/lastSync 字段**
- ☐ 未激活设备：hook 空转放行官方图
- ☐ 明文 imported 包不受影响
- ☐ activate 高频 → 1007（100 次/时）；packs 高频 → 429（120 次/时）
- ☐ 后台/商家重新登录正常；用旧 cookie 访问 → 跳登录页
- ☐ 商家解封 active 卡 → 恢复 active 且原 wxid 授权可用（prev_state 修复验证）
- ☐ 上传 0 图 zip → 拒收报错；散图非图片文件不被挪入 Assets/

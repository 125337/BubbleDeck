## 二、部署步骤

1. **备份数据库**（宝塔文件管理器，或命令行）：
   ```
   cp /opt/BubbleDeck_server/server/bd.db /opt/BubbleDeck_server/server/bd.db.bak_v1
   ```
2. **宝塔上传覆盖** 上述 6 个文件到 `/opt/BubbleDeck_server/server/`（templates 下 2 个进 `templates/`）
3. **重启服务**：`systemctl restart bdapi`
4. **清掉 V1 旧卡**（旧卡是全局卡语义、没绑包，留着无用）：
   ```
   cd /opt/BubbleDeck_server/server && python3 manage.py delcards
   ```
   （init 建表会在服务启动时自动给 licenses 表补 pack_name 列，旧数据无损，无需手工改表）
5. **带包重发测试卡**：
   ```
   python3 manage.py gencards 3 蜜糖邦尼气泡包
   ```
   或直接在后台「卡密管理」页发（现在必须选包）。
6. **线上自测**（拿一张刚发的卡号）：
   ```
   cd /opt/BubbleDeck_server/server && BD_SALT=<生产盐> python3 test_api.py https://qb.xhhan.xyz <卡号>
   ```
   预期 11 项 PASS（封卡项在线上模式自动 SKIP）。

## 三、注意

- **部署后旧 dylib 的激活会失败**（verify/download 接口已删）——属预期。V2 客户端 dylib 由我这边开发，两边都就位后再真机验收。
- 概览页「今日激活」等统计口径不变；`licenses` 表里 V1 遗留的 token/token_exp 列保留但不再使用，无影响。
- 封卡 = 后台「封禁」按钮，效果：该用户下次打开微信，「该卡对应包」自动失效，其他包不受影响。
